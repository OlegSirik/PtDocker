# Vars — системные правила

Проверять при генерации и изменении словаря атрибутов (схема → LOB → продукт).

## varType

Откуда берётся значение и как оно обрабатывается.

| varType | Смысл |
|---------|--------|
| **IN** | Поступает из запроса. |
| **VAR** | Присваивается в процессе работы системы. |
| **MAGIC** | Вычисляется встроенным кодом. |
| **CONST** | Задано конфигурацией продукта. |
| **OBJECT** | Узел JSON (группировка / объект в структуре). |
| **TEXT** | Внутренний тип; используется для подготовки печатных форм (шаблоны `{{varCode}}`). |

## varPath

Участвует ли атрибут в API и где он располагается.

- Если **путь заполнен** — атрибут является частью API (JsonPath в wire JSON запроса/ответа).
- Если **путь пустой** — внутреннее значение: может использоваться в контексте и расчётах, но **не попадает** в JSON-ответ API.

## isSystem

Защищён ли атрибут от изменения системно значимых настроек.

Если `isSystem = true`, **нельзя менять**:

- `varCode`
- `varType`
- `varDataType`
- `varPath`
- `isSystem`

Допустимы продуктовые рычаги там, где это разрешено уровнем (например `isDeleted`, `isTarifFactor`, `isOptional`, `varValue` / `varList` — по правилам уровня LOB/продукт), но не перечисленные выше поля.
