0. ПРИНЯТЫЕ УТОЧНЕНИЯ
═══════════════════════════════════════════════════════════════════

--- Страница / продукт ---
1. ns-policy, шаг оформления: insured02 (с полом M/F).
2. productCode = NS.
3. Целевая страница: ns-policy (не ns-quote). Маршрут /lk/ns-policy.
4. Вход: lk/quotes → «Создать» — статический список createProducts;
   пока только «Несчастный случай (NS)»; позже добавят pageId.
5. Сейчас только НС (ns-policy + quote-ns1). quote-klesh1 / антиклещ — отложить.

--- UI / стили ---
6. Оболочка страницы как у остальных (products/quotes):
   page-container + page-header + page-title.
7. Плашки блоков: mat-card, фон белый (класс policy-plaque).
   Общий стиль: features/policy-entry/styles/policy-plaque.scss.
8. Степпер: 3 шага (Предрасчёт / Оформление / Оплата).
   Индикатор шагов (не MatStepper с контентом внутри — зависания CD).
   Контент шагов через @if по store.stepIndex.
   Навигация назад: клик по достигнутому шагу в индикаторе ИЛИ кнопка «Назад».
   Вперёд по индикатору — только на уже достигнутые шаги;
   первый переход вперёд — через «Оформить» / «Далее к оплате».
9. Layout предрасчёта: левая ~60% ввод, правая ~40% результат.
10. Кнопка «Оформить»: активна только если premium > 0;
    ТОЛЬКО переход на шаг 2. Без save/quote.
11. Кнопка «Полис оплачен»: пустая заглушка, без API.
12. Не использовать ngModel+Date-объекты в datepicker (цикл CD / зависание).
    Даты UI: input type="date" + строки YYYY-MM-DD; store хранит wire ISO.

--- Предрасчёт NS (поля) ---
13. Виды спорта: захардкодить тестовые значения (FOOTBALL, HOCKEY, …).
14. Виды спорта UI: мультиселект, максимум 5.
15. Выбранные виды спорта: ПОКА НИКУДА НЕ ПИСАТЬ в Policy / draft
    (только локальный UI-state блока; маппинг позже).
16. Пакет: 0..5 → insuredObjects[0].packageCode как "0".."5".
17. Срок: блок policy-term — дата начала + список месяцев 1..36
    → policyTerm "P1M".."P36M". Дефолт: сегодня + P12M.
    endDate на вводе не задаём (считает backend).
18. Застрахованный на предрасчёте: birthDate, gender (M/F), sumInsured.

--- Оформление ---
19. policyHolderPerson: ФИО, birthDate, phone, email;
    документ select (пока PASSPORT / «Паспорт», расширяемый);
    только номер (без серии), dateIssue, whom, divisionCode;
    адрес регистрации — одно текстовое поле → addresses[0].addressStr.
20. insured02: ФИО, birthDate, gender M/F.
21. Данные застрахованного (person) копировать и в policyHolder.person
    (при изменении insured, перед quote, перед «Оформить»).

--- Wire JSON / API ---
22. Backend: POST .../sales/quotes|policies, @RequestBody String → PolicyDTO.
    Даты wire: ZonedDateTime ISO, напр. "2026-08-27T00:00:00Z"
    (не date-only "2026-08-27"). Пустой id "" ломает Long — не слать.
23. Пустые атрибуты НЕ передавать ("" / пустые объекты / пустые массивы).
24. Всегда массив "insuredObjects": [ ... ], никогда singular "insuredObject".
25. При «Рассчитать»: собирать JSON ЗАНОВО с нуля
    (PolicyService.buildFreshQuoteBody) — только поля ввода.
    НЕ использовать данные предыдущего расчёта (id, premium, covers,
    processList, status из ответа и т.п.).
26. Ответ quote НЕ перетирает draft ввода в store:
    пишем только premium (+ endDate для отображения при необходимости).
    resetQuote сбрасывает premium/endDate перед новым запросом.
27. Модели: shared/models (Policy, PolicyHolder, Person, InsuredObject, …).
    Store: PolicyDraftStore (providers на shell).

6. WIRE JSON (quote) — правила сборки
═══════════════════════════════════════════════════════════════════

Метод: PolicyService.buildFreshQuoteBody(policy)

Включать только заполненное, например:
{
  "productCode": "NS",
  "statusCode": "DRAFT",
  "startDate": "2026-08-27T00:00:00Z",
  "policyTerm": "P12M",
  "policyHolder": {
    "person": { "birthDate": "2000-06-14", "gender": "M", ... }
  },
  "insuredObjects": [
    {
      "ioType": "PERSON",
      "sumInsured": "500000",
      "packageCode": "0",
      "person": { "birthDate": "2000-06-14", "gender": "M" }
    }
  ]
}

Запрещено в запросе quote:
  — пустые строки / пустые объекты / пустые массивы
  — "insuredObject" (singular)
  — id: "" / поля прошлого ответа (premium, covers, processList, …)
  — date-only startDate без времени (нужен ZonedDateTime)
